🎯 Practice Project — Library Database

Design a small database with three tables: books, members, and loans (with primary & foreign keys). Then write queries: list all borrowed books with the member's name (JOIN), count loans per member (GROUP BY), and find members with more than 3 active loans (HAVING). This mirrors exactly how Frappe stores linked data.

🎯 Project 1 — Interactive To-Do List (DOM + Events)

Build a to-do app with plain HTML, CSS & JavaScript: add tasks, delete them, mark them done, and update the DOM live on each event. It exercises the whole Advanced JS section (DOM + Events).

▶ Tutorial — Build a To-Do List (HTML/CSS/JS)

🎯 Project 2 — Weather App (Fetch API + Async/Await)

The key project for backend-style JS: a user types a city, you fetch live data from the free OpenWeatherMap API, await the response (a Promise), then render temperature, humidity and conditions to the DOM — with error handling for a wrong city. This is exactly the pattern you'll use to call Frappe's REST API later, so treat it as essential, not optional.

ليه الـ Phase دي بتفرق؟

لحد هنا أنت أصلًا تقدر تدخل على Frappe مرتاح جدًا وتبدأ تبني Apps وتعدّل على ERPNext. لكن الـ Phase دي هي اللي هتفرّق بين واحد بيعرف يستخدم Frappe، وواحد فاهم هو بيحلّ مشكلة إيه أصلًا.

لو خلّصت المرحلة دي هتبقى مميّز في أي شركة، لأن أغلب الـ Developers للأسف بيعدّوها — يا كسل، يا إنهم شايفين Frappe مجرد Framework بيتبني بيه Apps ومش بيحاولوا يفهموا الـ Business Domain اللي النظام معمول عشانه.

المشكلة الحقيقية بتظهر أول ما ياخد Task من العميل: هتلاقيه واقف مش عارف يبدأ منين — مش لأنه مش بيعرف يكتب كود، لكن لأنه مش فاهم الـ Business Process. والمقصود بالـ Business هنا هو طريقة شغل الشركة نفسها: المخازن بتتحرك إزاي، المشتريات، المبيعات، المحاسبة، التصنيع، الموارد البشرية.

مثال: العميل قالك: «لما أعمل Sales Invoice، الكمية لازم تتخصم من المخزن، ولو العميل رجّع البضاعة في Return Invoice ترجع الكمية تاني.»

لو فاهم Python وFrappe بس، هتقعد تسأل: أخصم منين؟ وإمتى؟ الـ Sales Order بيخصم ولا الـ Delivery Note ولا الـ Invoice؟ وطب لو في Partial Delivery؟ ولو في Reserved Stock؟

لكن لو فاهم أساسيات الـ Inventory Cycle في الـ ERP، هتعرف إن السؤال مش عن الكود — السؤال عن Business Rules. ساعتها هتسأل العميل الأسئلة الصح، وتفتح كود ERPNext وتفهم ليه النظام متطبّق بالطريقة دي بدل ما تخمّن.

🎯 Practice Project — Run the Order-to-Cash cycle in ERPNext

No coding here — use the system as a business user. Get a free ERPNext trial, create an Item with stock, then run a full cycle: Sales Order → Delivery Note → Sales Invoice, and watch the stock quantity drop. Next, do a Return and watch it come back. Now you'll feel the business rules behind every DocType you'll later customize.
